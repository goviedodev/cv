# Application form answers — Lisit / Backend Developer (Remote)

Earlier I migrated core banking batch processes from AS/400 to Java for Santander, Ripley, and Coopeuch: reverse-engineer first, then reimplement without stopping operations — the same discipline this role's migration needs.

I work in both Node.js/TypeScript and Java/Spring Boot. At Perficient I worked Java 21/Spring Boot on Caterpillar's global e-commerce platform.

Since 2024 I've owned the backend of a mobility platform live in production (app.tellevoapp.cl) — PostgreSQL, Google Cloud, Pulumi. Coordinate data is daily work there, resolved via Google Maps APIs — not native PostGIS. I also designed the team's AI-assisted workflow (Claude Code, spec-to-verify cycle gated by automated tests).

## c) Why are you interested in working at Lisit?

Mainly the work itself. This role is a legacy-to-new-master migration onto PostgreSQL — exactly the kind of project where I've spent most of my career: understand a process nobody wrote yesterday, then move it without breaking what depends on it. At Citibank that meant Sybase to Oracle with 15M+ financial records and zero data loss; earlier it meant AS/400 batch processes to Java for Santander, Ripley, and Coopeuch. A high-concurrency normalization API on top of a large geographic data load is a harder, more interesting version of that same problem, not a new domain for me.

Second, the stack fits what I actually build day to day — NestJS/TypeScript and PostgreSQL — rather than a role where I'd be adapting my Java background to a language I don't use in production.

Third, working alongside the current backend owner instead of inheriting the system cold is the right way to run a migration like this, and it tells me the team takes the integrity risk seriously — which matches how I'd want to approach it.
