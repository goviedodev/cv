# Respuestas — Postulación FieldBeat (Desarrollador Backend Java)

## a) Cuéntanos sobre tu experiencia y perfil profesional

Soy desarrollador backend con más de 15 años construyendo y manteniendo servicios backend corporativos en Java. Hoy soy Tech Lead de una plataforma de movilidad en producción, donde diseño y mantengo el backend de APIs REST en Java 21 (Spring Boot), integrando además APIs REST de servicios externos (Google Maps: Directions, Distance Matrix, Geocoding) y el sistema de pagos (Transbank Webpay, Khipu) como endpoints del propio backend, con despliegues automatizados sobre Google Cloud (infraestructura como código con Pulumi) y Docker.

Antes de eso, en Citibank (2021–2022) desarrollé y mantuve servicios backend corporativos para los requerimientos mensuales del banco usando su framework interno (Java Bean Spring), y participé en la migración de la base de datos de Sybase a Oracle: más de 15 millones de registros financieros, sin pérdida de datos, en un equipo multicultural de EE. UU., Ucrania, India y Chile. Ese tipo de trabajo viene de una base más larga: 17 años en Santander/Isban (2000–2017) construyendo y manteniendo servicios backend para Préstamos, Medios de Pago, Cuentas Corrientes y Tarjetas de Crédito, atendiendo Chile, Puerto Rico, Colombia, Uruguay y Venezuela, con migraciones bancarias de AS/400 a Java.

Como Tech Lead en Seven IT (2017–2020) diseñé y desarrollé el backend de APIs REST del Sistema de Gestión en Salud de un hospital, en uso diario por personal clínico, y lideré técnicamente a 4 desarrolladores. En Perficient–Caterpillar (2022–2023) desarrollé y mantuve APIs REST del sistema de e-commerce global bajo Scrum, en un equipo distribuido entre EE. UU., India y Latinoamérica.

Para ser transparente: no he trabajado con Undertow ni con Azure Storage (Tables/Blobs) en producción. Sí tengo base sólida de Java (POJOs, concurrencia, serialización) que debería transferir bien a un servidor ligero como Undertow, y experiencia con Docker, Google Cloud y Azure DevOps. Uso Claude Code a diario como harness de desarrollo (flujo spec → plan → ejecución → verificación), un enfoque cercano al desarrollo asistido por IA y Spec-Driven Development que describe la vacante.

## b) Cuéntanos sobre tu formación académica y estudios

Soy Ingeniero en Ejecución en Computación e Informática, titulado en la Universidad del Bío-Bío (Concepción, 2005–2009). Mi tesis fue sobre Extreme Programming (XP), teoría y práctica — un enfoque iterativo que terminó marcando cómo trabajo hoy: entregas frecuentes, pruebas como puerta de calidad y feedback constante con el equipo.

Desde entonces mantengo formación continua por cuenta propia: progresé de Java 8 a Java 21 a lo largo de distintos empleadores (Santander/Isban, Citibank, Perficient–Caterpillar, Seven IT, y hoy en la plataforma de movilidad que lidero técnicamente), sumando arquitecturas cloud (Google Cloud, Azure DevOps) e infraestructura como código (Pulumi). En el último tiempo incorporé flujos de trabajo con agentes de IA generativa (Claude Code) aplicados al desarrollo de software en producción, algo que conecta directamente con la metodología Spec-Driven Development y la integración de IA en el flujo de ingeniería que describe FieldBeat.

## c) ¿Por qué estarías interesado en trabajar en FieldBeat?

Dos razones, en orden de peso.

**Por el desafío técnico.** El aviso describe el "motor" central de FieldBeat como una API REST de alto rendimiento en Java, procesando tráfico masivo (100M+ requests mensuales) con foco en concurrencia, escalabilidad y resiliencia. Es exactamente el tipo de responsabilidad backend en la que tengo más años acumulados: servicios backend corporativos en Java sostenidos en el tiempo, desde el procesamiento transaccional bancario en Citibank y 17 años en Santander/Isban hasta las APIs REST del Sistema de Gestión en Salud de Seven IT. No he trabajado antes con Undertow ni con Azure Storage específicamente, pero mi base de Java Core (POJOs, concurrencia, serialización) es transferible, y me interesa justamente ese tipo de arquitectura ligera y de alto tráfico como siguiente paso técnico.

**Por el enfoque de ingeniería con IA.** FieldBeat integra agentes de IA generativa como parte natural del flujo diario y trabaja bajo Spec-Driven Development — es exactamente cómo trabajo hoy: uso Claude Code a diario como harness de desarrollo, con un flujo de spec → plan → ejecución → verificación. No es una herramienta nueva para mí, es continuación directa de mi forma de trabajar. Sumado a eso, la modalidad híbrida real con oficinas en Providencia y el respeto declarado por el tiempo personal encajan con lo que busco en un próximo rol.
