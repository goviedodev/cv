## GCP

Mi experiencia en GCP viene principalmente de dos proyectos concretos:

- **Sistema de Gestión en Salud — Hospital Cruz del Norte (SQM)**, como CTO de Seven IT SpA (2017-2020): plataforma de control y registro de atención hospitalaria (medicina, enfermería, kinesiología) operando sobre Google Cloud (VM), con PostgreSQL y Linux como base.
- **Te Llevo App** (carpooling — [tellevoapp.cl](https://www.tellevoapp.cl) / [app.tellevoapp.cl](https://app.tellevoapp.cl)), como CTO & Co-founder (2024-presente): arquitectura completa en GCP con microservicios en Cloud Run, IAM y Logging/Monitoring.

En Te Llevo App configuré además los frentes de red y seguridad de GCP: **Cloud Armor (WAF)** y **Load Balancer**, con toda la infraestructura definida como código en **Pulumi (IaC)** — reglas de firewall, balanceo, permisos y secretos versionados en Git, sin configuración manual en consola.

Transparencia: no tengo experiencia productiva en **GKE** (mi trabajo con contenedores en GCP ha sido con Docker + Cloud Run). Dado el ritmo de aprendizaje que hoy permite apoyarse en IA para investigar patrones, mejores prácticas y resolver problemas de arquitectura, me comprometo a tener una solución funcional en GKE en no más de 2 días si el rol lo requiere — es, para mí, una muestra de que el código y la tecnología en sí son cada vez más un commodity: lo que diferencia es la velocidad y el criterio para llegar a la solución correcta, no el conocimiento previo puntual de una herramienta.

## DevOps

Tengo experiencia de punta a punta en el ciclo de despliegue, no solo en una etapa puntual:

- **IaC con Pulumi:** toda la infraestructura de Te Llevo App (cómputo, red, IAM, secretos) versionada como código.
- **CI/CD:** GitLab (Seven IT, Te Llevo), además de Jenkins y Azure DevOps en proyectos anteriores (Citibank).
- **Contenedores y despliegue:** Docker y Cloud Run en producción.
- **Seguridad de infraestructura:** WAF (Cloud Armor) y Load Balancer configurados y mantenidos como código junto con el resto del stack.

Un diferenciador que quiero destacar: uso IA de forma intensiva como parte de mi flujo de trabajo DevOps, no solo para escribir código — para investigar mejores prácticas, comparar alternativas de arquitectura y llegar más rápido a la mejor solución disponible para un problema dado. Esto acelera tanto el diagnóstico como la implementación.
